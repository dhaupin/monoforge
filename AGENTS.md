# AGENTS.md - monoforge

## Identity
- **Name:** monoforge (the fleet factory)
- **Repo:** dhaupin/monoforge
- **Core law:** generated green is never shipped; the doctor refuses placeholder text, missing entries, and broken gates; the lock refuses a dirty or failing tree.

## Mechanical conventions (this repo)

- **Prose flow (#49).** Living prose never hard-wraps at commit time: paragraphs flow, and `scripts/unwrap-prose.cjs` joins hard-wrapped prose without touching frontmatter, fences, indented code, tables, headings, thematic breaks, or HTML blocks. Dated history keeps its era wording.
- **Pins, never floats (packstruct#69).** Every GitHub Action `uses:` names a 40-hex commit SHA (tag kept in the trailing comment), never `@v4`/`@v1`. `npm run lint:pins` (`scripts/check-action-pins.cjs`) refuses a floating ref, so the rule is mechanical; it rides `npm run check` (the `prepublishOnly` gate) and CI. New pins take the family canon SHA the sibling repos already carry.
- Four factory verbs, one package, plus one opt-in lane: `new` (stamp from templates/), `doctor` (the truth battery), `cut` (release cuts: component-family workspace from a cutlist against a living lib), `lock` (doctor then archive), and `lint-packs` (the packstruct passthrough over the repo's own install, ready now as a loud refusal until the factory's own packs land). All zero-dep Node >=20 ESM in `src/`, CLI in `bin/forge.mjs`.
- The cut law: an unmapped internal dependency refuses loudly; shortfall lazies must be declared in cutlist.json and ship as documented call-site degrades (per-package README carries the list: absence is honest).
- Templates are extracted from PROVEN trees (poststruct + packstruct as of 2026-10-24). Add a block only when two instances prove it; a template block with a single instance is a bet, and the doctor cannot verify bets. The blocks live in PROFILE subdirs (`templates/<profile>/`, the coreforge shape), and a profile's `TEMPLATE.md` frontmatter carries a `chain:` list so profiles COMPOSE rather than duplicate: `monoforge` chains `monoforge-headless`, so the `.github/` battery lives once and both shapes inherit it. `src/templates.mjs` is the registry + chain resolver (`--list` / `--resolve NAME`); `stamp` copies the resolved set (children first, parent wins on a path collision, a cycle refuses by name), and `factory.json.profile` selects the profile (default `monoforge`).
- The storage seam (monoforge#27): the stamp engine touches the filesystem only through an injected adapter (`src/fs-adapter.mjs`), so it runs where `node:fs` does not exist. `src/fs-node.mjs` installs the real `node:fs` default and is imported ONLY by the Node entrypoints (`src/index.mjs`, `bin/forge.mjs`, `test/run.mjs`), so the CLI is unchanged; a workers consumer passes `memoryFs(seed)`. The engine core imports NO `node:*` at all - paths live in `src/paths.mjs` and the receipt hash is a pure-JS `src/sha256.mjs` (checked against `node:crypto`) - which is what lets `src/workers.mjs` (the `monoforge/workers` export: `stamp` + adapters, no `doctor`/`lock`) bundle for workerd. The compat claim is proven at the fam mount, not asserted: `web/functions/api/stamp-canary.js` stamps an in-memory tree at the edge and `web/scripts/build-canary.mjs` fails the build if any `node:*` reaches the bundle. Because that toolchain lives in `web/node_modules` and the battery runs a root `npm ci` only, the bundle + Function test lanes are a NAMED skip there (the CF Pages build covers them) and an always-on source-graph walk proves the no-`node:*` claim without esbuild.
- The headless harness (monoforge#23): `monoforge harness <verb> <dir>` (module `runHarness`/`run` from `monoforge`, `./harness` export) drives `new`/`doctor`/`lock` in-process and returns `{ verb, ok, verdicts, refusals, grant, receipt }` - the surface railyard's `railyard_stamp` consumes. Every refusal is `{ code, slot, detail }` and every code is REGISTERED in `spec/refusals.json` (the govstruct G10 shape, namespaced `monoforge`); `src/refusals.mjs` refuses to emit an unregistered code, so a typo cannot become a logged refusal. The doctor's `fail()` stamps `code` + `slot` from the exported `CODE_BY_ID` map (a fail id missing from the map is a bug `test/harness.test.mjs` catches). An optional grant `{ kind, scope }` is echoed back (kind, scope, `spent: true`) for the caller ledger (G5/G14); the forge never reads the credential. In-process only, no sockets. Adding a refusal code means adding it to `spec/refusals.json` first.
- The negative test in `test/run.mjs` asserts the refusal paths (bad config, stray dir), the doctor fail (unfilled) / pass (filled) pair, and the canon checks (monoforge#12 rider): a dangling `labs/.eyes/ledger.json` artifact pointer fails `dangling-canon`, an UNSET canon pin fails `canon-pin`, and a canon-free tree stays silent (the canon is opt-in; auditing nothing is never dressed up as a pass). Update the test in the same commit as any check change; run `npm test` first.
- The battery is one verb for CI and humans: `npm run check` (test + docs gates + language gate). The packstruct leg is deliberately not wired into check until the factory's own packs land; until then `monoforge lint-packs` answers exit 2 as the readiness probe. The phone publish lane rides the battery: `scripts/ship-from-download.cjs` is copied byte-as-is from eyestruct@9744c76 (zero repo imports) and `node --test test/ship-from-download.test.cjs` runs inside `npm test` (monoforge#14; the .cjs extension is the one mechanical rename the ESM root forces).
- The walk-exit rule (the promotion rule, family law 2026-10-28, eyestruct@70dfbea): a manual walk is not done until nothing it found is uncommissioned. A probe that only ever lived in prose is a one-mortem; the walk's exit criterion is that every finding became permanent in the same session (a battery leg, a pack verdict row, or a named docket row) so future walks only see fresh ground. Walks DISCOVER classes; the battery REMEMBERS them.
- The lanes are four workflow files: `.github/workflows/test.yml` (the battery, on `main` + `staging`), `docs.yml` (Jekyll + the six docs gates, its deploy job gated to `main`), `publish.yml` (the OIDC release ladder, refuses 0.x), and `staging-ff-sync.yml` (fast-forwards `staging` to `main` after every promotion). Before any tag, run the trifecta audit (README / AGENTS.md / deploy lanes / CHANGELOG, monoforge#10) recorded in DEPLOY.md.
- The staging branch (flowforge#30 / monoforge#20): `staging` is a permanent integration branch; work branches off it, PRs target it, promotion to `main` is the only path out. CI covers `staging` as well as `main`, any deploy job is gated `if: github.ref == 'refs/heads/main'`, and after every promotion `staging` fast-forwards to `main` (`git push origin origin/main:staging`). The flow rides `templates/monoforge-headless/.github/workflows/` (the headless profile) so a stamped repo inherits it; the full pattern is DEPLOY.md.
- The icon lane is the family's parameterized one: `npm run icons:adopt` (scripts/adopt-icons.mjs + scripts/brand-mark.json authored seal), same contract as gistory#17/eyestruct. Derived icon bytes are generated, not hand-drawn: the seal + the source art are the record.
- All prose submits to the voice law: zero dashes of any kind, no AI-cliche constructions, plain declarative sentences only.
